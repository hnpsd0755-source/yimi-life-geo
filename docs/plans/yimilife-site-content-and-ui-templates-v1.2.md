## 1. 本轮要确定什么

先确定页面职责、内容区块、先后顺序、客户下一步操作和模板形式；再设计桌面与手机 UI；最后填入核实后的资料、图片及英文文案。缺少图片、专利文件、证书或案例正文，不阻塞内容结构与模板设计。

本稿按现有页面制定建议，不创建新路由，不修改导航、官网代码、部署或现有预览。所有新增详情页均标为“模板预留”，不视为已存在或自动获准建设。

### 已明确的输入

- 定位：面向海外医疗品牌、渠道商和 OEM/ODM 客户的 B2B 医疗器械制造商。
- 一级产品分类扩展为五类：Pulse Oximeter（血氧仪）、Blood Pressure Monitor（血压计）、Wearable Monitoring Devices（穿戴监测设备）、雾化器、体温计。
- 雾化器子类目：压缩雾化器、手持微网雾化器。
- 体温计子类目：红外额温枪、体温贴、快速温度计。
- 新增品类与子类目先使用用户确认的中文名称；最终英文名称、型号、参数、图片及页面地址在后续阶段确定。分类确认不代表量产、上市、注册或验证状态已确认。
- 体温贴的主分类归入体温计；穿戴监测设备页如需关联展示，引用同一份产品信息，不另建重复详情。
- 首页主体：产品展示 → 公司介绍 → 研发展示 → 工厂展示 → OEM 合作案例；真实客户反馈作为案例内的可选内容。
- 可供后续填充的素材类型：专利墙、注册证书、Fluke 设备、实验室、研发团队。具体素材尚未逐份审查。
- 案例可以由公司根据真实项目整理撰写；不能把公司总结写成未经确认的客户原话。
- PulseMatrix™ 平台只作为血氧产品下的一个技术详情子页，不作为全站独立 Technology 栏目。low-perfusion、motion-artifact-rejection、skin-tone-fairness 只是该平台的三个技术方向或参数，在同一页内展示，不再规划三个独立专题页；具体参数值、测试条件与适用型号待核实，不通过设计稿增加技术能力或性能结论。

### 本轮不要求提供的内容

最终照片、具体专利清单、证书文件、完整产品参数、客户名称和案例正文。它们进入后续素材与内容填充阶段。

## 4. 各页应该展示什么

### 4.1 首页 Home

核心问题：你有什么产品、是谁、能否开发并制造、是否有可信合作经历？

按以下顺序设计：

1. 首屏：制造商定位、五大产品范围、一张主视觉；主按钮看产品，次按钮发起项目。
2. 产品展示：五大品类，品类图片、名称、一句说明、明确入口；雾化器卡注明两个子类目，体温计卡注明三个子类目。模板按五个入口安排主次布局或网格，不沿用只能容纳三张卡的固定布局；具体视觉方案后续评审，不塞参数表和完整定制流程。
3. 公司介绍：公司定位、服务客户类型、简短介绍、一张企业/团队图；进入 About。此区最短。
4. 研发展示：研发工作主图，实验室与专利辅助图，少量研发能力说明；进入 About 的研发内容；如引用 PulseMatrix™，只作为血氧产品技术详情的上下文链接。
5. 工厂与质量展示：生产线主图、检测/质量辅助图、少量确认数据；进入 Manufacturing & Quality。质量体系证书与生产检测图片放这里，避免复制研发照片。
6. OEM 合作案例：1 个重点案例＋可选补充案例。卡片包含项目类型、客户需求、我们承担的工作、实际阶段/结果；客户反馈仅在真实可用时加入。
7. 项目询盘：一句行动提示与统一 Contact 入口。
8. 页脚：页面索引和确认后的联系渠道。

不默认增加：独立重复的 Technology 大区、新闻区、FAQ 大区、五星好评墙、热门产品轮播、满意度计数。

### 4.2 产品总览 Products

核心问题：我应该进入哪个产品品类？

内容顺序：简短产品范围 → 五大品类大图卡 → 各品类下的产品形式摘要 → 型号/品类入口 → OEM/ODM 链接。

总览页不展示工厂长介绍、所有型号参数或每项技术原理。五个一级品类用清晰的目录卡片组织；雾化器、体温计卡内列出用户确认的子类目，并链接到相应分组，不因品类增加就默认引入复杂搜索筛选。

### 4.3 五大产品品类页

共同内容顺序：品类定位与主图 → 产品形式/型号分组 → 型号卡片 → 选中型号详情 → 配置/定制摘要 → 相关技术或质量入口 → 携带产品信息的询盘入口。

| 页面 | 品类内内容重点 | 不混入的内容 |
|---|---|---|
| Pulse Oximeter | 指夹式与手持式分组，真实型号差异、主图、关键参数和可选配置；PulseMatrix™ 技术详情子页入口 | 用抽象采购路径替代型号目录；首页式公司介绍 |
| Blood Pressure Monitor | 型号选择、测量形式、袖带与配件、显示/连接等已确认字段 | 为与其他品类凑齐而虚构功能分组 |
| Wearable Monitoring Devices | 产品形态、组成、佩戴与使用连接方式、参数；有 App 等功能时按资料填写；体温贴主分类归体温计，必要时仅关联引用 | 将新产品写成“未来储备”；擅自赋予量产、认证或验证状态 |
| 雾化器 | 压缩雾化器、手持微网雾化器两个分组；各组型号、产品图、关键参数、配件及定制入口 | 凭分类名称预填性能、适用人群、药物兼容性或治疗效果 |
| 体温计 | 红外额温枪、体温贴、快速温度计三个分组；各组型号、产品图、测温相关字段及询盘入口 | 将“快速”写成未经确认的测量秒数；预填测量精度、连接功能或注册状态 |

新增品类的共同布局：品类简介 → 子类目导航 → 各子类目说明与型号卡 → 选中型号详情 → 配件/定制 → 询盘。雾化器覆盖两组，体温计覆盖三组；资料后填阶段预留各组位置，不用虚构型号填满版面。

单一型号时：直接展示型号详情，不强行放筛选器、对比工具或重复卡片。
多型号时：先提供容易识别的型号卡，只有有实际差异且能帮助选择的字段才用于筛选。

### 4.4 型号详情内容模板（可内嵌，暂不创建新路由）

内容顺序：产品图集＋型号与名称 → 简短产品说明 → 关键规格 → 完整参数表 → 配件/配置 → 该型号的文件与注册信息 → 定制范围摘要 → 产品询盘。

需要定义的通用字段：型号、名称、一级品类、子类目（适用时）、主图/细节图、尺寸/重量、配件、可选项、对应文件；显示、供电、连接等按实际产品提供。参数表按品类切换字段，不给所有产品套同一组测量项。

雾化器预留雾化相关规格、使用与维护资料的位置；体温计预留测温方式、范围、精度、测量时间等适用字段。具体字段及数值按真实型号资料确认，不预填性能承诺。

血氧型号可按已确认的适用范围链接到 PulseMatrix™ 技术详情子页，不将平台的全部方向或参数默认赋予所有型号。

可选内容：下载、型号对比、演示视频、实际使用示意。没有资料时模板提供空态，不制造假文件、虚假认证图标或“已认证”通用徽章。

### 4.5 公司介绍 About（包含研发能力）

核心问题：这是一家什么样的公司，背后是谁在执行项目？

内容顺序：公司定位 → 公司简介及真实环境 → 团队与职责 → 研发工作场景 → 实验室及研发测试用途 → 专利积累 → 制造与技术内页入口 → 联系入口。

可选：确有必要且资料可核实的里程碑。默认不做大段历史、愿景口号和重复工厂规模统计。

研发资料分工：
- 团队：展示实际工作与专业职责，不预填人数或资历。
- 实验室：每张图配用途与工作环节，不只摆设备名。
- 专利：墙面图作辅助，详情按专利名称/类型/关联产品等真实字段填写。
- PulseMatrix™：如需引用，使用简短的血氧技术上下文入口，链接到血氧产品下的技术详情子页；About 不重复展开三个技术方向。

### 4.6 制造与质量 Manufacturing & Quality

核心问题：能否看见真实的生产环境，以及正式的医疗器械质量管理体系证据？

内容顺序：工厂全景与简短介绍 → 生产现场照片 → ISO 13485:2016 体系证书 → 紧凑联系入口。

模板预留：一张工厂全景、两张生产现场照片（生产装配、生产检验）、一份正式体系证书原件及核实后的简短说明。生产照片只配简短图注；证书保留原比例，实际图片、文件与说明后填。

本页聚焦公司级制造与质量展示，不再展开生产流程步骤、工位说明、产品检测项目、追溯字段、型号注册目录或产品文件分类。产品注册文件归对应型号详情，不以公司体系证书替代型号注册信息。

标准名称统一使用 ISO 13485:2016。当前为明确的文件占位，不表示已审查 YimiLife 证书的有效性、主体或适用范围；不制作假证书、假下载或预填认证结论。

生产检验照片可包含真实设备，但不展开型号级测试细节，不把设备存在等同于临床验证或准确性保证；研发用途素材继续归 About 研发区。

### 4.7 血氧产品技术详情：PulseMatrix™

页面归属：Products → Pulse Oximeter → PulseMatrix™。它是血氧产品的技术详情子页，不是独立 Technology 栏目，也不承担全公司研发介绍。

核心问题：PulseMatrix™ 为血氧产品关注哪些信号问题，相关技术方向或参数如何理解？

内容顺序：血氧产品面包屑 → 平台简介与示意 → 三个方向/参数区块 → 验证条件与可公开证据（资料后填）→ 适用血氧型号及范围 → 返回血氧产品/产品询盘。

三个区块均在本页内，使用统一的“方向说明 → 示意或参数字段 → 验证条件/证据 → 适用范围”结构：
- low-perfusion：低灌注方向或参数。
- motion-artifact-rejection：抗运动伪影方向或参数。
- skin-tone-fairness：全肤色公平性方向或参数。

它们不是三个独立产品、子平台或专题页。可用页内锚点辅助阅读，不再分配独立页面模板或“阅读专题”跳转。方向不自动等于量化性能指标；具体英文文案、参数值、测试条件与型号适用性在资料填充阶段核对。

采用 T07 血氧技术详情变体，保留清楚的血氧产品归属和返回路径。目标 URL 与旧技术地址的迁移在后续代码实施时处理，本轮只更新方案。没有测试数据时只做证据占位，不绘制虚构性能曲线。

### 4.8 OEM/ODM

核心问题：我的项目能以什么方式推进，双方各需要提供什么？

内容顺序：现有产品定制/新开发或修改产品入口 → 服务范围 → 具体可配置项目 → 分路径合作流程 → 阶段输入与输出 → 真实案例摘要 → 项目询盘。

已存在的品牌颜色/Logo 预览作为可选交互模块，模板阶段保留位置；它是外观沟通工具，不能表示所有配置都能生产或已经确认报价。

不预填：MOQ、开发周期、费用、交付承诺、默认认证责任。先预留字段及解释位置，后续用确认资料填写。

研发页展示执行能力；OEM/ODM 页说明合作方式，不复制整个研发介绍。

### 4.9 OEM 合作案例

目录页：简短说明 → 案例卡片 → 相关产品/OEM 服务入口 → 发起类似项目。

案例详情模板预留：
1. 项目背景：客户类型/地区和产品类别，按可公开程度填写。
2. 客户需求：实际要解决的问题。
3. YimiLife 工作：真正承担的定制、开发、验证或生产内容。
4. 项目过程：必要的关键步骤与图片。
5. 实际阶段/结果：已完成的事项；数字只在有记录时填写。
6. 客户反馈：可选，仅使用真实且允许公开的内容。
7. 相关产品与项目联系。

当前 /case-studies 的典型场景不是客户证据。模板设计可使用“案例标题待填”等明确占位，后续填入真实项目再安排公开内容。

### 4.10 资讯与知识 News

目录页：页面定位 → 内容分类 → 文章卡片 → 必要时分页；文章少时不做复杂筛选。

文章详情模板预留：标题、摘要、作者/更新信息（如实际维护）、正文、图片/图表、资料来源、相关产品和相关文章。

优先内容类型：产品选型、OEM/ODM 合作、技术说明、公司真实动态。具体选题另行研究，不以文章数量填充版面。

### 4.11 联系 Contact

核心问题：怎样把一个项目需求交给 YimiLife？

内容顺序：短引导 → 项目表单 → 确认的联系渠道 → 提交后的下一步说明。

建议基础字段：姓名、工作邮箱、公司、产品类别、需求说明。产品类别覆盖五大品类；选择雾化器或体温计时可进一步选择相应子类目（可选）。目标市场、预计数量、时间计划可选或渐进展开。产品页进入时可带入对应品类/型号，保留用户编辑权。

UI 模板必须包含：默认、必填错误、提交中、提交成功、提交失败并保留输入。具体字段必填性可在表单评审时调整。

当前实现使用 mailto，不等于已经接通服务器收件。这里只设计状态；真实发送、收件、附件和垃圾信息处理需要后续实施验证，不在视觉稿中假装已完成。

## 5. 八类 UI 模板骨架

以下是布局结构定义，供后续视觉设计使用，不表示八套视觉稿已完成。所有模板共用一套字体、颜色、按钮、间距、导航与页脚规范。

| 模板 | 页面骨架 | 桌面设计重点 | 手机设计重点 |
|---|---|---|---|
| T01 首页 | 首屏 → 产品 → 公司 → 研发 → 工厂 → 案例 → 询盘 | 产品权重最高；图文穿插；公司最短；研发/工厂图片用途不同 | 产品前置；每块先标题再核心内容；不连续堆叠多张大图 |
| T02 目录 | 页头 → 分类/条目卡 → 必要的翻页 → 相关入口 | 产品、案例、文章采用各自字段的卡片变体；统一图框与对齐 | 按卡片类型单列或紧凑列表；少条目不显示无用筛选 |
| T03 产品品类 | 品类简介 → 子类目/产品分组 → 型号网格 → 选中详情 → 定制/询盘 | 五大品类共用；雾化器两组、体温计三组；图片和型号优先，关键差异易比较 | 分组导航可换行；型号点击区域清楚；展开详情位置可定位 |
| T04 型号详情 | 图集/型号 → 要点 → 参数 → 配件 → 文件 → 询盘 | 图集与摘要双栏，按品类配置参数字段；同类产品字段顺序一致 | 图集在前；参数保持标签/值两列；长值换行，单位完整 |
| T05 公司/能力 | 页头 → 主题图文 → 证据 → 相关入口 | A 公司与研发、B 工厂质量各自排序，不强行同版同文；PulseMatrix™ 使用 T07 | 图片与说明成组；证书可放大；重要说明不靠悬停显示 |
| T06 OEM/ODM | 合作方式 → 定制内容 → 可选预览 → 流程 → 案例 → 询盘 | 区分 OEM/ODM 流程；交互为选择服务；预览不抢占流程主线 | 流程纵向；表单/配置不溢出；选择状态和下一步明确 |
| T07 内容详情 | 标题摘要 → 正文/图证 → 相关内容 → 行动入口 | 血氧技术详情（单一 PulseMatrix™ 页）、案例、资讯三个内容变体；保持阅读宽度 | 图注和证据随正文；目录可折叠；不依赖大横向图阅读 |
| T08 联系 | 引导 → 表单＋联系方式 → 状态反馈 | 主要区域用于填写需求；减少前置解释区 | 单列表单；明确错误位置；失败时保留输入 |

## 6. 素材后填的占位规则

设计稿预留的是内容类型和空间，不是虚构业务结论。

| 内容 | 占位方式 | 建议形状/约束（供设计，非最终素材要求） |
|---|---|---|
| 产品图片 | `[产品型号主图]`、`[细节图]` | 方形或 4:3，完整保留产品；统一背景与拍摄角度 |
| 公司/研发/产线照片 | `[研发团队工作图]`、`[产线主图]` | 主图约 16:9，辅助图约 4:3；标出主体安全区域 |
| 专利与注册证书 | `[专利文件]`、`[型号注册文件]` | 保留文件原比例，可放大；不裁掉识别信息来凑图框 |
| 数据 | `[经确认的数据]`＋实际字段名 | 为较长值和完整单位留空间；不填随机数字 |
| 产品卡文案 | `[产品名]`、`[一句用途/形态说明]` | 英文标题预留 2–3 行；正文约 20–35 词，最终按实际内容校验 |
| 案例 | `[项目标题]`、`[客户需求]`、`[实际工作]`、`[实际结果]` | 测试 1 条和多条内容状态，不制作虚假公司、Logo 或评价 |
| 资料下载 | `[文件名称与版本待填]` | 明确未填状态，评审预览中不提供假下载 |

占位标记仅用于内部方案和模板预览。正式页面资料未就绪时按内容重要性隐藏可选模块或保留现有真实内容，不把占位文案发布出去。

补充内容后还要复核排版：真实标题长度、图片主体、证书比例、参数单位及手机阅读效果。模板先行不意味着后续只换图片而无需检查。
