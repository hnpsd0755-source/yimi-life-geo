# YimiLife OEM/ODM 询盘功能与接口定义 V1.0

## 1. 已确认的六项决定

| 项目 | 用户确认结果 |
| --- | --- |
| 联系信息 | OEM 与 ODM 均要求姓名、业务邮箱、公司名称；目标市场和预计数量选填 |
| OEM Logo | 允许选择“稍后提供 Logo”，先提交需求和联系方式 |
| 附件规则 | OEM Logo：PNG/JPG/JPEG，1 个、不超过 2MB。ODM：PDF、Word（DOCX）、JPG/JPEG/PNG，最多 3 个、每个不超过 5MB，允许无附件 |
| 客户回执 | 自动发送确认邮件，包含询盘编号、需求摘要及团队将跟进的说明 |
| 内部通知 | OEM 与 ODM 共用一个统一业务邮箱，具体地址实施时提供 |
| 第一版后台 | 登录查看询盘、下载附件、标记跟进状态、查看及重试失败邮件通知 |

已确认总体方式：后台保存询盘和附件，再通知业务人员；同时向客户发送确认邮件。

## 2. 客户流程与页面调整

OEM：选择真实型号与颜色 → 选择定制需求 → 上传自己的 Logo 或选择稍后提供 → 填联系信息 → 查看摘要 → 明确点击提交。
ODM：选择品类及开发服务 → 填写需求与联系信息 → 可选添加资料 → 查看摘要 → 明确点击提交。

- 沿用当前颜色、字体、按钮和卡片，修改集中在表单、附件区、摘要及提交反馈。
- 选择文件和调整预览时在浏览器本地处理，明确提交后才上传。
- OEM 选择“稍后提供”也显示联系表单，不能继续仅用 Logo 文件名作为表单显示条件。
- 示例 Logo 只用于演示；选择示例继续时应标为“Logo 待补”，不能当客户原稿。
- 已选型号、颜色、定制需求和开发服务自动带入，避免客户重复填写。
- ODM 补姓名、预计数量、文件选择入口，并同步五个已确认品类。
- 上传区显示格式、大小、数量、已选文件与移除按钮；字段错误就地提示。
- 提交期间禁用重复点击。失败后保留当前页面的字段、配置和选定文件，允许重试；不承诺刷新或关闭页面后保留文件。
- 只有后台确认完整保存才显示成功和询盘编号；邮件发送结果单独记录。
- 保留资料用途说明；不得自动加入营销订阅，也不在回执中承诺固定报价或回复时限。

## 3. 统一输入字段

| 字段 | 适用与规则 |
| --- | --- |
| `contact.name` / `contact.email` / `contact.company` | 两区必填；邮箱校验格式，不仅凭邮箱后缀拒绝客户 |
| `project.targetMarket` / `project.expectedQuantity` | 两区选填；数量采用文本，允许说明单次、月度或年度估算 |
| `oem.modelId` / `oem.colorId` | OEM 必填、自动带入；正式环境从真实目录验证 |
| `oem.needs` / `oem.additionalRequirements` | OEM 可选定制项 ID 数组和补充说明 |
| `oem.logoMode` | OEM 必填：`uploaded` 或 `later` |
| `oem.preview` | 自有 Logo 的画布尺寸、底图标识、渲染版本及调整参数 |
| `odm.categoryId` | ODM 必填，涵盖五大确认品类；内部 ID 不等于已批准的公开英文名称 |
| `odm.serviceIds` / `odm.brief` | 服务 ID 数组可空，需求正文必填，允许客户尚不明确具体开发服务 |

真实型号、颜色和服务使用稳定 ID，后台核对并保存提交时的显示名称与配置快照，避免以后目录变化改变旧询盘含义。演示型号不能直接用于生产询盘。

## 4. Logo 和附件

OEM 上传自有 Logo 时，在同一询盘中保存：原始文件、最终产品预览图、配置参数。原稿保持原始字节；去白底、透视及颜色处理不能覆盖原稿。原稿供设计使用，预览图供业务沟通，参数用于还原选择，不作为印刷尺寸指令。

现有参数：`offsetX`、`offsetY` 为 CSS 像素，`rotation` 为角度，`scale`、`width`、`height` 为百分比，`tone` 为 original/dark/light。必须连同画布宽高、底图与渲染版本记录，避免不同设备下只凭像素偏移还原错误。
`logoMode=later` 不要求 Logo 文件和调整参数，仍保存其他需求。

ODM 允许零至三个附件，格式限 PDF/DOCX/PNG/JPG/JPEG；旧版 DOC、压缩包等不在第一版范围。
工程阈值延续现有实现：2MB 为 2×1024×1024 字节，5MB 为 5×1024×1024 字节，边界值允许。

后台校验实际格式、数量、大小和文件所属询盘。文件名用于展示，存储使用独立标识，附件须授权访问。邮件不提供公开永久文件地址。
系统生成的预览图不占 ODM 客户附件名额；其压缩上限在实现时根据服务容量确定。

选型须验证“三个 5MB 文件＋字段和请求开销”能够提交。如单次请求容量不足，可采用临时上传加最终确认，保持已确认额度与客户的一次提交体验。

## 5. 接收接口（实施基准，尚未创建）

入口：`POST /api/inquiries`。
采用 `multipart/form-data`：一个 JSON 文本字段 `metadata`，加实际文件。浏览器设置 Content-Type 与 boundary。

| 请求部分 | 内容 |
| --- | --- |
| `metadata.schemaVersion` | 固定为 `1` |
| `metadata.submissionKey` | 本次提交唯一标识；相同内容重试复用，客户编辑内容后重新生成 |
| `metadata.type` | `oem` 或 `odm` |
| `metadata.contact` / `metadata.project` | 第 3 节共同字段 |
| `metadata.oem` / `metadata.odm` | 只提供与类型对应的对象 |
| `metadata.source` | 页面路径与界面语言，不携带私人查询参数 |
| `logoFile` | OEM `uploaded` 时必填的原始 File |
| `previewImage` | OEM 自有 Logo 的最终预览图；生成失败时提示并保留输入，不发送旧图 |
| `attachments` | ODM 文件体，同名字段重复，最多三个 |

后台分别验证 OEM/ODM 规则；不能只接收文件名、本地地址或截图而遗漏原稿和配置。
如选择的服务需改动传输步骤，记录字段映射，保持上述已确认业务规则。

| 响应 | 语义 |
| --- | --- |
| `201` | 询盘与必需附件完整保存，通知任务已记录；返回 `inquiryId`、`receivedAt`、`status: received` |
| `200` | 相同 submissionKey 与相同内容的重试，返回原编号 |
| `409` | 同标识但内容不同，按修改后的新提交处理 |
| `400` | 字段/JSON/格式错误，返回可定位的 `fieldErrors` |
| `413` / `415` | 超限 / 文件实际格式不支持，定位附件并说明原因 |
| `429` | 频率限制，提示稍后重试并保留输入 |
| `5xx` | 保存或服务异常，返回可理解的提示及 `retryable` 标记，不假报成功 |

响应不包含后台凭据或私有存储路径。后台以唯一提交标识和内容摘要防止重复请求创建多条询盘与重复通知任务。

## 6. 保存和通知规则

校验 → 暂存附件 → 完成询盘、附件关联及通知任务记录 → 返回编号 → 分别发送内部通知和客户回执。

- 完整保存后才对客户确认接收；附件失败不能留下一条显示为完整接收的记录。
- 数据库和文件存储分离时明确失败补偿与临时文件清理，避免无文件的记录或孤立文件。
- 响应丢失后，相同请求重试返回同一编号。
- 邮件失败不删除询盘、不要求客户重传；内部通知与客户回执分别记录状态、尝试时间和次数。
- `queued/sent/failed` 是邮件任务状态；sent 表示邮件服务接受发送，不保证已进入收件箱。
- 内部通知包含编号、联系信息、需求、Logo 是否待补、附件数量及需登录的详情入口；发件人为公司发信身份，回复地址可以是客户邮箱。
- 客户回执包含编号、本人需求摘要和后续沟通说明，不附后台管理地址或私人文件链接。

## 7. 后台操作和接口预留

所有管理操作需要登录授权，询盘编号本身不构成访问权限。第一版一个业务管理角色即可，具体登录方案随后台服务确定。

| 功能 | 接口预留 |
| --- | --- |
| 分页查看、筛选询盘及邮件状态 | `GET /api/admin/inquiries` |
| 查看需求、配置快照、预览、附件 | `GET /api/admin/inquiries/{id}` |
| 授权下载附件 | `GET /api/admin/inquiries/{id}/attachments/{attachmentId}` |
| 标记 new 待处理 / in_progress 跟进中 / closed 已关闭 | `PATCH /api/admin/inquiries/{id}`，记录人员和时间 |
| 重试失败邮件 | `POST /api/admin/inquiries/{id}/notifications/{notificationId}/retry`，防止并发重复重发 |
